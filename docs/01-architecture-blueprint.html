1.4 Key design decisions & rationale

Azure CNI Overlay

Pod IPs come from 192.168.0.0/16 overlay, not the VNet, so a /25 node subnet is enough and the design scales without re-IPing. Day-0 decision - changing later means recreating the cluster.

Spot user pool + tiny system pool

The system pool (1×B2s, ~$30/mo) runs kube-system. All app workloads go to the spot pool (up to ~90% cheaper) via tolerations. Spot evictions trigger the autoscaler / workload reschedule; acceptable for a POC.

Two ACRs, not one

Matches the reference architecture and creates a hard boundary: CI can only push to non-prod; prod receives copies of already-validated digests. Blast radius of a compromised pipeline is halved.

Workload Identity + OIDC, zero secrets

--enable-oidc-issuer --enable-workload-identity on the cluster, WIF service connection in Azure DevOps, KV CSI driver in pods. No stored credentials anywhere in the chain.

Environments = approval gates

Azure DevOps Environments (aks-staging, aks-production) carry Approvals checks - the audit-friendly way to implement the manual intervention box in the diagram.

Helm push-model default, ArgoCD optional

Pipelines push Helm releases (simple, works everywhere). ArgoCD is provided as the pull-model alternative where Git is the desired-state source and merges are the approval mechanism.

1.5 Naming, versioning & release standards

Resource naming

<type>-<prefix>-<env>         rg-hexaks-dev, aks-hexaks-prod, vnet-hexaks-dev
<type><prefix><purpose><seq>   acrhexaksnp001 / acrhexakspr001  (ACR: alphanumeric only)
<type>-<prefix>-<seq>          kv-hexaks-001, grafana-hexaks-001 (globally unique)

Container image tagging policy

TagProduced byRegistryMutable?
<buildId> (e.g. 42)CInon-prodNo - one tag per build
<shortSha> (e.g. 9f1a2b3)CInon-prodNo - traceability to commit
dev-latestCInon-prodYes - convenience pointer only
<semver> (e.g. 1.4.0)PromoteprodNo - locked immutable
<semver>-prodPromoteprodNo - locked immutable

Environment flow

DEV (non-prod ACR)→ QA→ UAT→ STAGING (aks-dev ns staging)→ PROD (aks-prod ns production)

For a POC the logical DEV/QA/UAT stages collapse onto the single staging namespace/cluster using tags + Helm values - the promotion pipeline and tagging scheme already support adding dedicated namespaces/clusters later without redesigning.

Release strategy

  • Trunk-based: short-lived feature branches → PR → squash merge to main.
  • Release: run the Promote pipeline with the CI tag + semver. Optionally cut a Git tag v1.4.0 on the same commit.
  • Deploy: CD pipeline deploys to staging automatically; production waits on Environment approval.
  • Rollback: Helm --atomic auto-rolls-back on failure; manual rollback = redeploy previous immutable tag (never rebuild an old tag).
