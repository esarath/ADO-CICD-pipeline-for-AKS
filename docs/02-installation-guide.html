0. Pre-flight tasks (mandatory, ~10 min)

0.1 Task 1 — Choose and set globally-unique resource names

Four resources in this design get public DNS names, so their names must be unique across all of Azure (not just your subscription). If any name is already taken by someone else, the deployment fails partway through.

ParameterFileRulesCheck availability
acrNonProdName infra/bicep/params/platform.bicepparam 5–50 chars, lowercase letters + digits only, no dashes az acr check-name --name acrhexaksnp001
acrProdName same rules az acr check-name --name acrhexakspr001
keyVaultName platform.bicepparam 3–24 chars, letters/digits/dashes, must start with a letter deploy will error if taken — pick a rare suffix (e.g. your initials + date: kv-hexaks-jd26)
grafanaName platform.bicepparam 2–23 chars, letters/digits/dashes same — change suffix if deploy reports a conflict

What to do:

  1. Run scripts\00-prerequisites.ps1 first (it installs the CLI and logs you in) — or at minimum run az login + az account set --subscription 995377ec-18d5-43bb-98db-74ab68a2ef8f.
  2. Check both ACR names: 
    az acr check-name --name acrhexaksnp001
az acr check-name --name acrhexakspr001
    If nameAvailable: false comes back, change the 001 suffixes to something personal (e.g. acrhexaksnp-jd26 → remember: no dashes allowed in ACR names, use acrhexaksnpjd26).
  3. Open infra/bicep/params/platform.bicepparam and set your final names in acrNonProdName, acrProdName, keyVaultName, grafanaName.
  4. Open infra/bicep/params/dev.bicepparam and prod.bicepparam and set the same three names (acrNonProdName, acrProdName, keyVaultName) so the environment deployments reference the correct shared resources.

0.2 Task 2 — Keep names consistent everywhere they are consumed

The same names are referenced in three different places. They must match exactly or pipelines will fail with "resource not found" errors.

Name / valueWhere it must match
acrNonProdName, acrProdName, keyVaultName ① platform.bicepparam (creates them)
② dev.bicepparam + prod.bicepparam (RBAC wiring)
③ Azure DevOps → Library → variable group platform-settings (pipelines read these as $(acrNonProdName) etc.)
Service connection sc-azdo-aks-platform ① Created once in Project Settings → Service connections (script 03 §2)
② Referenced literally in all 4 pipeline YAMLs as azureSubscription: 'sc-azdo-aks-platform' — if you name yours differently, do a find-and-replace across pipelines/
Variable group platform-settings ① Created once in Pipelines → Library (script 03 §3)
② Referenced in all 4 pipeline YAMLs as group: platform-settings; must contain acrNonProdName, acrProdName, keyVaultName, aksDevRg, aksDevName, aksProdRg, aksProdName
Environments aks-staging / aks-production ① Created once in Pipelines → Environments (script 03 §4)
② Referenced in azure-pipelines-cd.yml as environment: targets — prod environment carries the Approvals gate
adminObjectId Auto-filled by 01-deploy-infrastructure.ps1 from az ad signed-in-user show --query id — no manual step needed unless deploying Bicep by hand
Rule of thumb: the Bicep param files are the single source of truth for resource names. Whatever you type there must be copied verbatim into the platform-settings variable group. The Azure DevOps objects (service connection, environments) are fixed names baked into the pipeline YAMLs — create them exactly as spelled, or find-and-replace in pipelines/.

0.3 Quick self-test before continuing

az account show --query name          # must print: adminebooks
az acr check-name --name <your-np>    # must print: "nameAvailable": true
az acr check-name --name <your-pr>    # must print: "nameAvailable": true

If all three checks pass, proceed to Phase P0.

2.6 Phase P5 - Hardening & handover Week 4

  • Confirm Defender for Containers recommendations flowing (24-48h for first scan results).
  • Import AKS dashboards in Managed Grafana (browse → Azure Monitor dashboards).
  • Optional: install ArgoCD on the dev cluster and compare push vs pull models (doc 04).
  • Optional: enable App Routing (az aks approuting enable) for managed nginx ingress.
  • Set a Cost Management budget + alert on the subscription (doc 06).
  • Write access reviews: who can approve the aks-production environment.
